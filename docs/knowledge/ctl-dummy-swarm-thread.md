# 仿真集群必须跑在独立线程的事件循环里

`remote/dummy.py` 提供仿真受控端（真 `RemoteService` + 真 WS/gRPC 服务端，只换掉
抓屏与输入）。每台自带屏幕尺寸 / 延迟 / 操作日志，`--fail-ops` 可给最后一台注入故障。

`DummySwarm.serve_in_thread()` 不是可选的便利措施，**是必需的**：

> 若集群与控制端跑在同一线程的事件循环里，控制端一阻塞，服务端的 loop 就停转。
> 现象是「所有机器一起超时」—— 极易误判成分发层坏了，其实是测试自己的问题。

假屏幕 / 假输入从 `test_remote.py` 提到 `dummy.py`，两边共用一份，避免各写一套漂移。
