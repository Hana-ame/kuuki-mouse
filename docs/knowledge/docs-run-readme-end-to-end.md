# 照 README 逐条真跑一遍，比单元测试有用

写完整使用说明之后，把 README 里每条命令**真跑一遍**（13 组场景 / 34 项断言）：
起服务 → 等就绪 → 客户端真连 → 杀掉。

**它比单元测试有用，因为它走的是「用户照文档抄」这条路径** —— 单元测试测的是
「代码对不对」，这个测的是「文档说的能不能做到」。当场抓到：

1. `wincheck.py` 一跑就崩（`Capture` 没有 `backend` 字段）—— 没有任何测试会执行它
2. README 里 ctl 的 endpoint 格式写错
3. `--qr` 只在 PeerJS 开着时有意义，只开 `--ws` 时静默什么也不做 → 补进启动前拦截

## 写这类验收脚本的坑

- **判断「服务起来了」不能用 `"已启动"`** —— "WebSocket 服务已启动" / "gRPC 服务已启动"
  这两行 INFO 里也含它，会在别的传输还没就绪时就判定完成。用**只在最后一张端点清单
  打印完才出现**的标记（本项目是 "客户端示例"）
- ctl 的 registry **每轮要删** —— 同名别名会报「已存在; 要覆盖加 --force」
- **连不通的机器别混进 `ping --all`** —— 会把整条命令的退出码带歪，看不出是用法错
  还是机器挂了
