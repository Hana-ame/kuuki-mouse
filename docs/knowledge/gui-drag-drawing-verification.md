# 落笔画线的回测: 三个必须守住的环节 (前台 / 找色板 / drag 时长)

## 现象

`mouse.drag(points=[...])` 在画图 (mspaint) 上拖红色波浪线与圆, 第一次跑**画上了**,
第二次跑却"画布上红色块 0 处"、脚本判定"没画上"。同一份脚本、同一套坐标, 两次
结果完全不同。

## 为什么: 三个各自独立的坑

### 1. 只确认一次前台是不够的

脚本开头 `ensure_paint()` 确认了 mspaint 在前台, 然后一路往下走。**但真人就在
这台电脑旁边** —— 中途用户切回了自己的窗口 (WorkBuddy), 于是:

- 后续截图截的是别人的窗口, 画布上的红色"消失"了;
- 更危险的是 `mouse.drag` 也被拖到了别人身上 (Windows 下拖动 = 选中/拖放,
  可能真做出点什么)。

`window.foreground` 查一次只代表"这一刻"。**每个关键动作之前都要查+抢**:
点色板前、每次 drag 前、验证截图前。

### 2. 找色板必须限定窗口顶部条带

`find_color(region=窗口矩形)` + "取最大的一块"看起来很稳, 但**画布上已有的
红色笔迹比色板方块大得多** —— 最大块是笔迹, 于是"点色板"变成了"在画布上点一下"
(画笔模式下就是又画一个点), 颜色状态根本没变。

修法是把 region 收成窗口顶部条带 (色板所在的 `y < 120`):

```python
strip = (box[0], box[1], box[2], min(120, box[3]))
```

**"取最大块"这个启发式只有在 region 已经排除了干扰物的时候才成立。**

### 3. `mouse.drag` 的 duration 是**每段**的时长

源码里写得清楚: `duration` 是每段时长, 总时长 = `duration × (点数 − 1)`。
25 个点的圆 × 1.2s = **28.8 秒**。想要快速一笔, 要么点采样稀疏些, 要么直接
调小 duration —— 别按"整条路径的总时长"给值。

## 更稳的回测写法

`evidence/calibration/verify_draw.py` 现在的顺序:

1. `ensure_paint()` 打开/激活画图, 复用或重做 `screen.calibrate`;
2. **顶部条带内**找色板红块 → 点它 (便宜且不会错, 保证前景色是红);
3. `ensure_fg()` → `mouse.drag` 拖波浪线;
4. 画完立刻截图, 用 `stroke_coverage` (见另一条: 聚簇中心不能当定位证据) 判断
   有没有画上; 没画上就点一下工具区的画笔图标, 再画个圆补验;
5. `ensure_fg()` → 验证截图 → 网格证据图 + 报告。

## 教训

- **自动化脚本里"状态确认"是动词不是名词**: 前台、目标、颜色状态都可能在两次
  op 之间被真人改掉, 关键动作前重查一遍, 别缓存结果。
- 真机验收脚本的失败分两类: **工具坏了** (真 bug) 和 **环境变了** (前台被切)。
  先查前台再查代码 —— 本轮浪费的两轮重跑都属于后者。
