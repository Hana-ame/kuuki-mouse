# 验证"画在哪个位置"别用 find_color 的块中心 —— 聚成一簇时中心落在空白处

## 现象

画图上画了红色波浪线 (预测中心约 `(725,350)`) 和红色圆 (预测中心 `(720,540)`),
`find_color` 返回两块:

```
(724,348) 453x123     <- 波浪线, 与预测完全吻合
(607,455) 183x183     <- "圆"? 比预测偏了 (-113,-85), 像是画歪了
```

脚本按"块中心离预测路径多远"判定, 于是报"没画上"。**但笔迹其实画得很准** ——
沿预测圆周 72 个采样点查像素, 56 个点 ±3px 内有红; 波浪线 17 个采样点全部命中。

## 为什么

`find_color` 的聚簇是**松散邻接**: 两个形状即使不连通, 只要网格距离够近就可能连
成一簇 (波浪线下沿 y≈410 与圆上沿 y≈450 相隔 40px, 在 cell 聚类的蔓延半径里被
桥接了)。一簇只报一个外接框, 而**外接框的中心不等于任何形状的中心** —— 那个
`(607,455)` 正好落在两形状之间的空白区域。

所以:

- 一块 = 至少一个目标, 但**块数不等于形状数**, 块中心不等于形状中心;
- 当画面上有多个同色目标时, "块中心"这个量根本不对应任何真实位置。

## 该用什么: 沿预测路径逐点查像素

```python
def stroke_coverage(image, path, pad=3):
    """预测路径上每一点 ±pad 内出现目标色算命中, 返回命中率。"""
```

这条判据的好处是**直接对应"笔迹有没有落在打算画的地方"**: 命中率 100% 就是
分毫不差, 60% 说明有局部偏移, 0% 才是真没画上。它也不依赖聚簇行为, 不会被
"两个形状连成一簇"骗到。

`find_color` 仍然有用 —— 用来回答"这个颜色在不在画面上、大概多大", 但**不要
拿它的 center / area 当精确位置证据**。

## 附带: 目测证据图也会骗人

预览里图片被等比缩放显示 (1280px 的图渲染成 ~1054px), 目测读出来的坐标一律
偏小 (×0.82)。当时"看图觉得圆画在了 (607,455)"其实是因为 find_color 的数就是
那么报的, 而图上贴着圆周的黄十字 (预测点) 才是真的 —— **判据要用像素算,
不要用眼睛量缩略图**。

## 教训

- 视觉 API 返回的"块"是聚类产物, 不是物体。需要精确位置就回到像素。
- 验收脚本的判据要能区分"没画上"和"判据本身不可靠": 后者浪费的排查时间更多。
