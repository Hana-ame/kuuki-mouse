# PeerJS 超时要比「实测握手时间」大，不能拍脑袋

真机实测：注册到 `0.peerjs.com` 约 2 秒，**握手本身要 13 秒**。而库里的默认超时是
10 秒 —— 于是每次都在握手即将成功前放弃，表现为「怎么都连不上」。已改 30 秒。

```bash
python -m remote.peerjs_selftest    # 真跑一次的入口（假屏幕假输入，不动光标）
```

**教训**：这类数字不要用「感觉够长」来定。链路里最慢的那一段决定了下限，得实测。
同一次的其它实测数字：192457 字节截图经真实 DataChannel 分块传送，逐字节相同。

## 验证 PeerJS 的两层做法（可复用）

光靠逻辑分析不够，光靠真机又太慢且依赖外部服务。拆两层：

1. **下层（我们的代码）用内存回环**：一对假 `DataConnection` 把 `PeerJsServer` 与
   `PeerJsClient` 背靠背接起来，`send()` 就是一次函数调用 —— 不经过 broker / ICE，
   但跑的是与真机**相同的代码路径**
2. **上层（网络）留自检入口真跑**：`remote/peerjs_selftest` 打到真实 broker

第 1 层进单元测试（不受外网影响），第 2 层留给人工确认。
