# 房间码是配对用不是凭证；token 提示要按传输分三种

## 房间码挡不住针对性

PeerJS 房间码是 5 位字符（字符集 31，约 2860 万种）。它**只挡误撞**，挡不住枚举或
有意试探。要真保护得加 `--token`：

```bash
python -m remote --room ABCDE --token <随机值>
```

README 里对此有明确说明，别写成「房间码已足够安全」。

## `token:` 那行提示不能一概而论

曾经无论开了哪些传输都打 `token: 未设置 (仅回环安全)` —— 这在**开着 PeerJS 时是错的**：
PeerJS 是本机连出去注册到公开 broker，与绑 `127.0.0.1` 还是 `0.0.0.0` 无关，
「仅回环安全」这个说法不成立。现在按实际开启的传输分档给出提示。

## 相关的一条

`--allow-remote` 在**没有任何本地端口传输**时不起作用（PeerJS 不绑端口），
这种情况会明确提醒，而不是让人误以为已经「允许远程」。
