# 启动前拦截：新语义才会出现的组合

开关改成「点名即选择」后，出现了两种**旧语义下不存在**的组合，如果不拦，它们的
表现都是「看起来正常，实际什么都不做」。两者都拒绝启动（退出码 2）：

1. **一个传输都没开**（例如单独的 `--no-peerjs`）—— 否则起个什么都不监听的空壳，
   用户以为在跑
2. **给了 `--ws-port` / `--grpc-port` / `--room` / `--qr`，却没开对应传输** ——
   换了端口服务却没起来，静默失败

第 2 条需要能分出「8765 是默认值还是用户手打的」，所以这些端口参数用了自定义的
argparse Action（`_RememberPort`）记录「显式给过」。**默认值和显式值在 argparse
里长得一样**，不额外记一笔就无从判断。

另外：**传输校验要排在 `--selftest` 之后** —— 自检不起任何服务，不该因为
`--no-peerjs` 就没法自检。
